# ADR-0016：四站 cache 架構約定（前端只讀 cache、後端全包）

- **編號**：ADR-0016
- **日期**：2026-10-16
- **網站**：四站
- **狀態**：Accepted

## 背景與原因

2026-10-16 一天之內四站新增了多種動態數據做法（ETF 後端刷新、travel RSS 自動頁等）。星哥追問禱告處境頁的自動化是「網頁自己做的還是 Muse 在這邊做」、代碼是自寫還是 configuration，並指出隱憂：若邏輯有的寫在前台、有的寫在後台，四站各長各的，過一年必亂——需要一條統一的後台邏輯規矩。

## 決策內容

星哥定版（原話要點：前端只從 cache 讀；TTL 由我們自己定，半小時、兩小時、五小時皆可；也可以手動刷新 cache；所有服務的前端只讀 cache，其他都不做；API 抓數據、拼內容全由後端做）：

1. **前端只讀 cache**：四站前端永遠只讀 cache 顯示，不許直接打外部 API、不許瀏覽器端抓數據拼邏輯。
2. **後端全包**：數據抓取、雙源核對、拼接、寫入 cache 全由後端負責（invest 走後端服務；無獨立後端的站，其網站服務端層即後端，如 travel 的 ISR 實現）。
3. **TTL 配置化**：每類數據按性格自定（30 分鐘／2 小時／5 小時皆可），不許寫死在頁面邏輯裡。
4. **手動刷新**：後端須提供手動刷新 cache 的入口。
5. **失敗降級**：刷新失敗時前端繼續讀舊 cache 並帶 stale 標記，頁面不許壞。
6. **新功能一律照此約定**；誰要在前端加邏輯，先停下來問星哥。

## 誰拍板

星哥拍板（定版，長期約定）。
